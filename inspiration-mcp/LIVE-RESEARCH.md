# Up2Data audience research

Enter the target audience, then the work or offer you want to write about. The collector uses the audience to find source material. The draft step uses the offer after you select interests.

**Fetch with Up2Data** first checks unexpired matching request records. When audience member profiles are available, it requests a page of their authored posts (up to 25 per profile). Otherwise, it searches recent posts using the audience description. The research step must establish author fit before including a search result. Missing or uncertain matches can leave the map empty. The intake profile belongs to the founder and is excluded from audience sources.

Set **Maximum credits** to a whole number from 1 to 100 (default 10). Before a new paid request the local Mac asks the owner to approve the audience and cap. The run is scoped to the audience and current Berlin date; changing the offer or adding profiles does not renew that audience's allowance. Prior reservations count. The collector enforces its cumulative ceiling and stops at an unaffordable request. If the approval is canceled or unavailable, the app can still use existing evidence.

**Build map from evidence** uses the cache or an imported source set without a paid request. The app does not search local founder writing. Selecting topics, generating sample posts and exporting Markdown use no Up2Data credits.

See the [profile activity](https://docs.up2data.ai/v1/api/profiles-activity/) and [post search](https://docs.up2data.ai/v1/api/search-posts/) provider documentation.
